## 三、修改过程（按迭代顺序）

### 1. 打通装甲检测（传统视觉）

- 思路：HSV 分色 → 灯条候选 → 灯条配对 → 大小板判定 → 置信度加权 → NMS。
- **问题 1**：仿真画面里灯条是青色，H≈90，落在最初设定的蓝色区间 95–135 之外，一条都检不到。
  → 把蓝/青下限下调到 **85**。
- **问题 2**：仿真里灯条很细（约 4×28 px），面积阈值 90 px² 把真实灯条过滤掉了。
  → 面积下限降到 **35 px²**，同时保留长宽比、倾角等几何约束。
- 验证：1440×1080 仿真帧上稳定检出靶车装甲，角点顺序正确。

### 2. 画框与录制

- **问题 3**：角点用 `reinterpret_cast<cv::Point*>` 把 `Point2f` 当 `Point` 读，坐标变成乱码，框画到屏幕外。
  → 改为逐点 `cvRound` 转换。
- **问题 4**：首版录了 39 秒，超出 20 秒限制，且包含启动阶段。
  → 重录后裁掉启动段，固定 20.0 秒。
- 录制方式：程序内 `VideoWriter` 直接写显示画面（避免窗口被遮挡、缩放影响画质）。

### 3. 训练数据返工（重要）

- **问题 5**：首版训练集是我用检测器对仿真帧做**自标注**得到的 300 张，不符合“使用老师下发数据集”的要求。
  → 全部弃用，改用 `dataset.zip`：14 类装甲板，17996 张筛出 7046 张带标注，
  train 5637 / val 1409，类别 `B1–B5 / BO / BS / R1–R5 / RO / RS`。
- 训练：YOLOv8n，640×640，batch 16，35 epochs，RTX 4060 约 25 分钟。
- 结果：**P 0.932 / R 0.826 / mAP50 0.902 / mAP50-95 0.775**。

### 4. 视频兼容性

- **问题 6**：播放器报“需要 H.264 解码器”（本机缺 `gstreamer1.0-libav`），High profile 兼容性也差。
  → 重编码为 **H.264 Constrained Baseline**，并额外提供 VP9 的 `webm` 预览版，
  同时在 GitHub Release 挂了直链。
- 结论：文件本身无问题，是播放器缺解码器；提交仍用 mp4。

### 5. 增加能量机关识别

- **需求**：除装甲外还要识别能量装置。
- 实现（传统视觉）：黄色圆形 R 标记 → 颜色 + 圆度 + 面积过滤 → 每个标记输出一个观测。
- 同时用老师的 `能量机关数据集.zip`（YOLO Pose，620/10，5 关键点）训练了 **YOLOv8n-pose**：
  框 mAP50 **0.995**，关键点 mAP50 **0.962**（验证集只有 9 个目标，波动大）。

### 6. 按反馈调整框的形态

- **反馈 1**：能量机关不要用一个大框把整个装置包进去，要每个圆形小装置一个小框。
  → 返回类型由 `optional<Rune>` 改为 `vector<Rune>`，每个标记单独外扩 15% 出小框。
- **反馈 2**：装甲的绿框要能装下整块装甲板。
  → 灯条外沿算出角点后，围绕中心外扩 **宽 ×1.35、高 ×2.05**（大小板判定仍用灯条比例）。
- **反馈 3**：录制时以前后移动为主，不要过多转视角。
  → 驱动脚本改为 `W/S` 为主、`A/D` 小幅横移，云台基本不动。

### 7. 修复误检

- **问题 7**：截图显示能量机关旁边的**支架/栏杆**被识别成装甲板（`SMALL 0.75`）。
- 原因：支架上两根竖直橙色条被当成灯条，外接框宽高比约 1.4，刚好高于原阈值 1.35。
- 修改：
  - 最小宽高比 **1.35 → 1.60**；
  - 新增**灯条粗细一致性**约束：两根灯条宽度差 > 50% 直接丢弃。
- 验证：从演示视频抽 40 帧回归，**40/40 仍检出真实装甲**，新视频中该误检消失。

## 五、问题与反思

1. **域差是最大问题**：两个网络都是在老师提供的**真实图像**上训练的，直接拿到仿真画面上用，
   装甲网络框会错位、能量机关网络零检出。所以演示视频用的是传统检测器，网络产物单独提交。
   下一步要解决“真实数据 → 仿真/实车”的迁移。
2. **交付物要考虑对方环境**：视频因为对方播放器缺 H.264 解码器打不开，是多花了一轮才发现的。
   以后交付视频默认用 Baseline + 附带 webm 兜底。
3. **误检要从几何约束下手**：这次支架误检是宽高比和灯条一致性两个约束一起解决的，
   比单纯调置信度阈值更稳。
